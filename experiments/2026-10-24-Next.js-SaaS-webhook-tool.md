## Idea

Anyone building a receiver for this app's outbound webhooks has no way to produce a correctly
signed test event without running the whole app and a database. Add `pnpm webhook:tool`, an
offline CLI that builds a body in the dispatcher's exact shape, signs it with the existing
`signWebhook()`, verifies a signature, and prints a ready-to-run curl command.

Other ideas considered: an `env:check` doctor for `.env.example`; a generated plan-comparison
table from `PLANS`.

## Success checks

1. `pnpm -s webhook:tool sign --secret s3cret --event demo.ping --payload '{"hello":"world"}' --timestamp 2026-01-01T00:00:00.000Z`
   prints the body `{"event":"demo.ping","payload":{"hello":"world"},"timestamp":"2026-01-01T00:00:00.000Z"}`
   and a 64-character hex signature equal to
   `printf '%s' "<that body>" | openssl dgst -sha256 -hmac s3cret` for that exact body.
2. `pnpm -s webhook:tool verify --secret s3cret --body '<body from check 1>' --signature <sig from check 1>`
   exits 0 and says the signature is valid; the same command with `--secret wrong` exits non-zero
   and says it is invalid.
3. Adding `--curl http://localhost:4000/hook` to the check-1 command prints a curl command that
   POSTs to that URL with `Content-Type: application/json`, `X-Webhook-Event: demo.ping` and
   `X-Webhook-Signature: <sig>` headers and the same body (the same headers `dispatcher.ts` sends).
4. The CLI signs through `signWebhook()`/`verifySignature()` from `src/lib/webhooks/signer.ts`:
   no second HMAC implementation (`grep -rn createHmac src scripts` finds only `signer.ts`, plus
   any pre-existing hits unrelated to webhooks).
5. A new vitest file for the CLI logic passes with at least 5 tests, and `pnpm typecheck`,
   `pnpm lint` and `pnpm test` all pass.
6. `README.md` documents the command under "Add a new webhook event".
